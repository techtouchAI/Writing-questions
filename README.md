# صانع ومحرر الأسئلة

[![Build & Release Android APK](https://github.com/techtouchAI/Writing-questions/actions/workflows/build_apk.yml/badge.svg)](https://github.com/techtouchAI/Writing-questions/actions/workflows/build_apk.yml)

تطبيق Flutter عربي (RTL) لإنشاء بنك أسئلة، تجميع اختبارات، وتصديرها كورقة **PDF بصفحة A4 واحدة** جاهزة للطباعة — إضافة إلى تصدير بنك الأسئلة بصيغة **Excel (`.xlsx`)** من جهاز Android.

## الوظائف الرئيسية

- إنشاء وتعديل أسئلة: اختيار من متعدد، صح/خطأ، إكمال الفراغ، وأسئلة مقالية.
- إدخال **هيكلی** للمادة: اختيار المادة من قائمة معرفة، وأقسام مسبقة لكل مادة
  (القواعد/الأدب/إنشاء للغربية العربية، أحكام التلاوة/الحفظ/... للتربية الإسلامية)،
  وفروع سؤال (أ، ب، ج...) بدرجات مستقلة.
- تصنيف السؤال حسب المادة والموضوع ومستوى الصعوبة والدرجة.
- بحث وفلاتر مستقرة حسب النص والنوع والصعوبة والمادة.
- بناء اختبار من أسئلة البنك، ترتيبها عشوائياً، وحفظ ترويسة قابلة لإعادة الاستخدام —
  مع بيانات وزارية مهيكلة (المديرية، الشعبة، نوع الاختبار، التاريخ) وزمن يُحسب
  آلياً حسب قواعد الوزارة.
- تصدير ورقة الطالب أو نموذج الإجابة كملف **PDF** مع **معاينة داخل التطبيق**
  (طباعة/مشاركة عبر حزمة printing)، وتصدير بنك الأسئلة بصيغة Excel.
- حفظ البيانات محلياً على الجهاز. يعزل التطبيق السجلات المحلية التالفة حتى لا يمنع سجل واحد تالف بقية البيانات من الفتح.

> الاختبارات المحفوظة تحتفظ بلقطة من أسئلتها؛ حذف سؤال من البنك لا يعدّل اختباراً محفوظاً سابقاً دون قصد.
>
> **تجميد Word/Excel للامتحانات الرسمية:** تصديرات Word (وكذلك Excel للاختبارات)
> موقوفة للامتحانات الرسمية حفاظاً على التنسيق الثابت غير القابل للكسر؛ ورقة
> الاختبار الرسمية تُصدَّر PDF حصراً. تصدير Excel متاح لبنك الأسئلة (البيانات).

## معالج النموذج الوزاري (Wizard) ومحرك المعاينة A4 متعدد الصفحات

مسار إنشاء متسلسل يحاكي النماذج الوزارية العراقية (2026/2027)، يُفتح من بطاقة
«نموذج وزاري جديد» في الشاشة الرئيسية، ويعمل جنباً إلى جنب مع بنك الأسئلة
وبانى الاختبار الحاليين دون حذف أي أداة:

1. **الترويسة** (`ExamHeaderModel`): ثلاثة أعمدة × ثلاثة أسطر (يمين: التاريخ/المادة/الصف،
   وسط: الوزارة/المدرسة/امتحانات نصف السنة والدور، يسار: الوقت/الاسم/الرقم الامتحاني)
   مع تعبئة وزارية افتراضية بضغطة واحدة.
2. **إعداد السؤال** سؤالاً سؤالاً («إعداد السؤال الأول» ثم «الثاني»...): يبدأ بالفرع (أ)،
   و[إضافة فرع جديد] يضيف (ب) ثم (ج) بنفس الأدوات (`BranchEditorCard` يغلّف
   `McqOptionsEditor` و`LtrNumericField` ونماذج صح/خطأ والفراغات الحالية). [التالي]
   يحفظ ويفتح سؤالاً جديداً فارغاً، و[إنهاء وعرض النموذج] ينتقل للمعاينة.
3. **المعاينة A4 (WYSIWYG)** (`ExamPreviewScreen`):
   - **تقسيم ورقي ديناميكي**: كل كتلة (الترويسة/السؤال الكامل) تُقاس عبر `MeasureSize`
     ويعيد `PaginationEngine` (منطق خالص في `lib/layout/`) توزيعها؛ **السؤال وحدة لا
     تتجزأ** — إن لم يتسع بفروعه في المساحة المتبقية انتقل كاملاً إلى الصفحة التالية.
   - **تحرير مباشر**: كل نصوص الورقة حقول قابلة للكتابة في مكانها.
   - **سحب وإفلات مخصص**: سحب فرع وإفلاته على فرع آخر يبدّل `content` و`marks` فقط
     (`ExamDocument.swapBranchContent`)؛ الهيكل الرقمي (السؤال الأول - أ) ثابت.
   - **الأدوات العائمة**: نفس `SmartExamToolbar` (صور، مثلث/دائرة/مربع، صيغ LaTeX)
     تثبّت العناصر فوق مساحة الفرع المحدد وتُسحب وتُغيَّر أبعادها.
4. **قوالب المواد** (`SubjectLayoutTemplate`): التربية الإسلامية (أحكام التلاوة/الحفظ/الفهم
   والتفسير/التربية الإسلامية)، اللغة العربية (القواعد/الأدب والنصوص/الإملاء/الإنشاء)،
   الإنجليزية (LTR كامل، Q1/Q2 وA/B/C)، والمواد العلمية (مساحات أوسع للمعادلات وأرقام
   لاتينية) — يُشتق القالب من مادة الترويسة ويستهلكه العرض والطباعة معاً.
5. **الطباعة**: `PaginatedPdfExamEngine` يولّد PDF بحجم A4 متعدد الصفحات بنفس توزيع
   الصفحات المعروض على الشاشة (`pageAssignments`) ونفس خط Noto Naskh Arabic، مع
   `FittedBox(scaleDown)` كشبكة أمان ضد أي تجاوز.

إدارة الحالة عبر `ExamWizardController` (`ChangeNotifier` + `provider`) يفصل الواجهة عن
منطق التقسيم والتبديل؛ النماذج تُحفظ محلياً عبر `ExamDocumentProvider`.

## محرك ورقة الاختبار (PDF Engine)

وحدة مستقلة داخل `lib/pdf_engine/` مسؤولة عن رسم ورقة الاختبار على «لوحة» A4
ثابتة بدقة المليمتر، وفق ثلاثة مبادئ:

1. **صفحة واحدة مضمونة هيكلياً**: يُبنى مستند `pw.Page` واحد فقط، ومنطقة الأسئلة
   داخل `FittedBox` بوضع `scaleDown` — أي أن أي تجاوز للمحتوى يؤدي إلى تصغير
   الطباعة آلياً وبتناسق كامل داخل المساحة المتبقية، لا إلى خروج الأسئلة عن الورقة.
2. **نمط الاستراتيجيات (Strategy Pattern)**: كل مادة لها استراتيجيتها
   (`ArabicExamStrategy`، `IslamicExamStrategy`، `EnglishExamStrategy`،
   `GenericExamStrategy`) تحدد الاتجاه (RTL/LTR) وتقسيم الأسئلة إلى أقسام —
   لا شجرة شروط داخل المحرك.
3. **نماذج بيانات صارمة**: الترويسة (`ExamHeader`) والسؤال (`Question.category`،
   `Question.branches`) مهيكلة بالكامل؛ لا يُترك أي حقل وزاري لنص حر غير محسوم.

اختيار الاستراتيجية يتم من اسم المادة عبر `ExamStrategies.forSubject(...)`.

### الخطوط والترخيص

يستخدم التطبيق خط **Noto Naskh Arabic** (خط واجهات Google من عائلة Noto، رخصة
SIL Open Font License — النص في `assets/fonts/LICENSE-OFL-NotoNaskhArabic.txt`).
نسخة Google كاملة التغطية: محارف العرض العربي (Presentation Forms) للحروف
المتصلة + كامل اللاتينية والأرقام، وهو شرط لرسم العربية سليماً داخل PDF.

### مسافات الكلمات العربية (نسخة `pdf` معدّلة محلياً)

يستعمل المشروع نسخة محلية من حزمة `pdf` 3.11.3 في `third_party/pdf` (عبر
`dependency_overrides`) تحمل تعديلاً واحداً: في `_Line.realign()` كان موضع
الكلمة في النص من اليمين إلى اليسار يُحسب بعرض **الحبر** بدل عرض **التقدّم**،
فتتآكل المسافة بين الكلمات (‏«تدورالأرض» بدل «تدور الأرض»). التحقيق الكامل
والقياسات قبل/بعد في `docs/arabic_word_spacing_fix.md`، وتفاصيل النسخة
وطريقة تحديثها في `third_party/pdf/README-VENDORED.md`، وحراسة الفحص في
`tool/verify_vendored_pdf_patch.dart` + اختبارات
`test/pdf_engine/arabic_word_spacing_test.dart`.

## المتطلبات

- Flutter **3.22.3** (Dart 3.4 أو أحدث ضمن نطاق المشروع).
- Android SDK وJava 17.
- جهاز Android أو محاكي للتشغيل المحلي.

## التشغيل محلياً

```bash
flutter pub get
flutter analyze --fatal-infos
flutter test
flutter run
```

ولإنشاء APK للإصدار:

```bash
flutter build apk --release
```

ينتج الملف في:

```text
build/app/outputs/flutter-apk/app-release.apk
```

> إصدارا `pdf` و`printing` مثبّتان بدقة في `pubspec.yaml` لضمان توافق CI
> مع Flutter 3.22.3؛ لا ترفَعهما إلا مع تحديث إصدار Flutter في الـ CI معاً.

## توقيع إصدار الإنتاج

لا تُحفظ مفاتيح التوقيع في المستودع. يبني CI ملف APK قابل للتثبيت باستخدام مفتاح debug فقط عند غياب إعدادات الإنتاج؛ **لا توزّع هذا الملف كإصدار إنتاجي**.

لإنتاج APK موقّع للإصدار، أنشئ الملف غير المتتبع `android/key.properties`:

```properties
storePassword=YOUR_STORE_PASSWORD
keyPassword=YOUR_KEY_PASSWORD
keyAlias=YOUR_KEY_ALIAS
storeFile=/absolute/path/to/your-release-key.jks
```

ثم نفّذ أمر البناء نفسه. أضف المفاتيح إلى أسرار CI الخاصة بك عند إعداد نشر إنتاجي؛ لا تضعها في Git.

## التحقق المستمر

يتحقق GitHub Actions من كل دفع إلى `main` وفروع Arena، ومن طلبات السحب إلى `main` عبر المراحل التالية:

1. تثبيت Flutter 3.22.3 وJava 17.
2. استرجاع الحزم.
3. التحقق من وجود إصلاح مسافات الكلمات العربية في النسخة المحلية من `pdf`.
4. تحليل المصدر مع اعتبار المعلومات التحذيرية فاشلة.
5. تشغيل اختبارات الوحدات والواجهة (ومنها اختبارات مسافات الكلمات العربية
   التي تقيس ملف PDF الناتج فعلاً وتفشل لو عاد الخلل).
6. بناء APK للإصدار ورفعه كأثر بناء لمدة 14 يوماً.
7. عند دفع وسم يبدأ بـ `v`، إرفاق APK تلقائياً بإصدار GitHub المقابل.

## البنية المختصرة

```text
lib/
├── models/       # نماذج صارمة: الأسئلة (فئة/فروع)، الترويسة الوزارية، قواعد الزمن،
│                 #   ونماذج المعالج (ExamHeaderModel/QuestionModel/BranchModel/ExamDocument)
├── layout/       # محرك التقسيم الورقي الخالص (PaginationEngine) ومقاسات الورقة المشتركة
├── pdf_engine/   # وحدة PDF المستقلة: الاستراتيجيات، محرك صفحة A4، المحرك متعدد الصفحات
├── providers/    # الحالة، الفلاتر، متحكم المعالج، والحفظ الذري مع التراجع عند الفشل
├── services/     # التخزين المحلي وتصدير PDF/DOCX/XLSX (Word مجمّد للامتحانات)
└── views/        # واجهة RTL وشاشات الإدارة والبناء والمعاينة والتصدير
    └── wizard/   # خطوات المعالج: الترويسة ← السؤال ← معاينة A4 (WYSIWYG)
test/             # اختبارات النماذج، المحرك (صفحة واحدة)، والاستراتيجيات
                    #   (ومنها قارئ PDF مستقل واختبارات مسافات الكلمات العربية)
third_party/pdf/  # نسخة محلية من حزمة pdf 3.11.3 + إصلاح مسافات RTL (Apache-2.0)
tool/             # سكربتات الحقن والتحقق من تعديل الحزمة
android/          # إعداد Android حديث باستخدام Flutter Gradle Plugin
assets/fonts/     # Noto Naskh Arabic (OFL) لخط الـ PDF
```
