# P2 layout inventory — before canonical-engine implementation

Baseline branch starts at P1 commit `d392018c60d8c38b4aafabd8e16287a07f9310aa`. This inventory is intentionally written before P2 implementation. It records current geometry owners and duplicates; P1 semantic IR remains the semantic source and is not a layout result.

## Detailed production locations

- `lib/layout/visual/visual_flutter_style.dart`: conversion from pt to logical px, `TextAlign` conversion, plus P0-F `TextPainter` line-count/word-spacing approximation. It is currently called by both `PaperField` and `TexText`, but the PDF does not call it.
- `lib/views/widgets/paper_field.dart`: editable text uses Flutter's normal wrapping; `_resolveEffectiveStyle` applies paragraph-level spacing for justify. Rich content is delegated to `TexText`.
- `lib/views/widgets/tex_text.dart`: builds text/math/Quran spans; layout-time `LayoutBuilder`; own call to P0-F word-spacing helper; inline `WidgetSpan`; block math gets independent vertical padding/centering.
- `lib/views/wizard/exam_preview_screen.dart`: `_buildPage` assembles `Column` children and spacing; `MeasureSize` drives pagination; `_buildQuestionBlock`/`_buildBranchBody` create `Column`/`Row`; `_titleRow` decides constrained widths; `_pointRow` and `_buildPointOptions` create run geometry and `Wrap`; divider and legacy attachments add more widget height; `_buildPageStack` reserves header/footer regions; `FittedBox(scaleDown)` handles an overflow page. `FloatingElementView` gets independent overlay geometry.
- `lib/providers/exam_wizard_controller.dart`: `_blockHeights`, `reportBlockHeight`, `footerReserve`, `pagination`, `pageAssignments`, `questionRect` and float clamping use Preview-measured geometry.
- `lib/pdf_engine/pdf_paper_builder.dart`: header/footer rows/columns; question/branch columns and frames; title rows; points and options rows/wrap; divider sizing; rich `_renderText`/`_plainText`; math raster width/height; legacy attachment reserved space.
- `lib/pdf_engine/paginated_pdf_exam_engine.dart`: PDF widget measurement, second `PaginationEngine` path, page top/float placement, A4 geometry, and page-wide `pw.FittedBox(scaleDown)`.
- `lib/pdf_engine/floating_elements_pdf.dart`: PDF-side float/text-box/formula rendering, own text/math `pw.Wrap`, authored source width/height to pt, rotation/shape sizing.
- `lib/layout/pagination_engine.dart`: pure flow paginator; keeps each `PageBlock` together, moves it on natural overflow, permits a single oversized page block to overflow. It has no line/block geometry and reports only page block IDs and used height.
- `lib/layout/visual/visual_typography.dart` / `visual_style.dart` / `visual_metrics.dart`: shared typography and spacing intent exists, but metrics are documented in px and are only converted at adapter boundaries. `visual_document.dart` has a separate unused block model.
- `lib/layout/document_ir.dart`: semantic nodes, direction, style references, header/footer/questions/options/attachments. It deliberately has no positions, measured geometry, or page assignments. `FloatingElementReference` omits source x/y/dimensions/rotation/page index, which must be resolved through an external resource/layout-input adapter.
- `lib/services/math_snapshot_renderer.dart` / `pdf_math_rasters.dart`: one reusable math rendering source (`flutter_math_fork`) and point-size raster dimensions; today dimensions are consumed by PDF wrapping and not by Preview's canonical line geometry.

## P2 migration decisions

1. Keep authored document data in `ExamDocument`/`DocumentIR`; put all resolved points, line/run boxes, scale decisions, page assignments, and break reasons in `LayoutDocument`.
2. Add centralized pt/mm/px/twips conversions. A4 dimensions are defined from 210×297 mm; no `794` constant enters the canonical engine.
3. Hide Flutter `TextPainter` behind an injectable measurement interface. The interface returns primitive layout/metric records only; no `TextPainter`, Flutter `TextStyle`, or `pw.*` object appears in `LayoutDocument`.
4. The same `LayoutDocument` is passed to a Preview geometry view and a PDF painter. PDF uses positioned drawing only; the old `PdfPaperBuilder` remains as the P1/DOCX compatibility input path until P2 migration is verified.
5. Float source geometry is resolved through an external stable-ID resource resolver. Global floats are page-anchored; owned attachments are content-area/question-anchored; formulas/images remain inline or block-flow only where explicitly requested. Unsupported anchors stay marked deferred rather than being silently converted to flow.
6. `FittedBox.scaleDown` is classified as a legacy overflow fallback. The canonical engine resolves the scale factor and records it; the Preview and PDF may not pick scales independently. The page-zoom `BoxFit.fill` remains UI chrome, outside layout.
7. DOCX stays on its P1 semantic adapter. Its known geometry/pagination limitations are tracked as P3 rather than injected into this engine.
